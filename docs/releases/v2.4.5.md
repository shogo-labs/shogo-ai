# Shogo 2.4.5 release write-up

Release plan, test plan and rollback notes for **v2.4.5** — a patch on the 2.4
line. Russell asked for a release in #go-live on 2026-10-30 ("lets do a 2.4.4
release"), then chose the patch number after the `v2.4.4` collision below was
pointed out ("then do a 2.4.5 release").

> **Why not 2.4.4.** `v2.4.4` already shipped: the desktop-watchdog /
> machine-copy hotfix (#1802), tagged `65420f10a` on 2026-10-28 and published
> 11:17Z. Production still reports `version: 2.4.4`, `buildHash: 65420f10a`.

> **Why there is no changelog entry and no announcement email.** Per
> `apps/docs/changelog/_README.md`, patches are not published: they roll up into
> the next minor entry, and only minors/majors get a What's New entry and an
> announcement. `v2.4.1`–`v2.4.4` shipped the same way. The draft `v2-5` entry
> written for the first version of this plan is kept in Appendix A so the next
> minor can start from it.

## Known risk accepted for this patch

**1. #1813 was never exercised on a physical device or on Android.** Its own PR
body says *"Not yet tested on a physical iPhone"* and leaves *"Verified no
regressions on Android and web"* unchecked. It was tested on the iOS simulator
and by CI's phone e2e (iPhone 15 Pro WebKit + Pixel 7, green). It is a 99-file
mobile-only change, so the blast radius is the phone app. Russell merged it
himself (`lacvapps`, 2026-10-30 00:49Z) on his explicit instruction ("get this
merged"). Watch the phone app after the roll: keyboard on the chat composer,
Back from project chat / canvas / files / plans, tab switches, Android.

**2. `e2e/local/chat-resume-on-send.test.ts` failed on #1813's pre-merge run.**
Three specs — `:528`, `:577` and `:600` ("… then the user sends a message") —
failed on the initial attempt and both retries, each at ~2.7 min, in run
[40979922464](https://github.com/shogo-labs/shogo-ai/actions/runs/40979922464).
The job log shows the agent provider aborting turns
(`[AgentLoop] Provider error from pi-agent-core: Request was aborted`), which is
the shape of a provider/infra flake rather than a UI regression, and the same
job is green on `fix/video-upload-playback` (40929554629) and
`fix/mention-rendering` (40926729594). **It was not re-verified after merge**:
`40a73cedd` is mobile-only, so the path filter skipped every `E2E (local mode)` /
`E2E (chat resume)` / `E2E (phone)` job on the merge commit and on the merge-queue
run. If chat resume misbehaves after this roll, this is the first place to look —
and it is the one thing in this release that is green-by-skip rather than
green-by-run.

## Rollback note

`Rollback Production` to `v2.4.4` is safe:

- Every migration is additive: a new `workspace_moves` table and nullable
  columns on `workspaces` / `workspace_moves`. A 2.4.4 api ignores all of them.
- A move that is **in flight** when you roll back stops advancing (the runner
  lives in the new api). The job row and the id map stay on disk, so rolling
  forward resumes it; nothing is half-written, because records and files land in
  idempotent chunks.
- Desktop publish: a new desktop talking to a rolled-back cloud api gets a `404`
  on `/api/published-sites/*` and reports it — already-published sites keep
  serving, and nothing is deleted.
- #1813 is client-only: a phone on the old build keeps the old motion, and the
  app is unaffected by an api rollback.
- **Metal agent:** no node-agent change in this release; rolling it back is not
  required.
