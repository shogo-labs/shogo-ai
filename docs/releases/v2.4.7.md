## Known risk accepted for this patch

- **Delta reads (SHO-260)** are the biggest behavioural change: a client with a
  stale cursor must handle `reset` by downloading the page again. The route
  shares `scopeChatMessages` with the list route so a delta cannot be authorized
  or filtered differently from the page it replaces, and the desktop/mobile
  caches fall back to a full page on any unparseable delta. A rollback is safe:
  an old client ignores the new endpoint and the extra column.
- **`ALTER TYPE … ADD VALUE`** (`build_ready`, `credits_reset`) cannot run inside
  a transaction block on older Postgres; the deploy ran it on staging first and
  the critical-path e2e was green there before the tag.
- **Activation funnel columns** are read by background jobs and analytics only;
  a value missing means "not reached", never an error.

## Rollback note

`Rollback Production` to `v2.4.6` is safe:

- Both migrations are additive: one column with a default plus an index, and
  three nullable columns / two enum values. A 2.4.6 api ignores all of them.
- A device that cached transcripts under the new schema keeps them; the delta
  endpoint 404s on a rolled-back api, and every client falls back to the full
  page it downloaded before.
- Activation jobs simply stop firing; the pending flags stay on disk so rolling
  forward resumes them (`capNotifyPendingAt` still owed → sent once).
- No metal agent change is required to roll back the api.
