# Shogo 2.4.11 release write-up

Release plan, test plan and rollback notes for **v2.4.11** — a patch on the 2.4
line, cut from `main` at `16ca77bd2`.

**Shipped** 2026-11-03T16:02:43Z: tag `v2.4.11` (`f9ae797e0` → `16ca77bd2`),
25 assets on the GitHub release (macOS arm64/x64 `.dmg`, Windows `Setup.exe`,
CLI/worker tarballs, auto-update feeds).

> **Why there is no changelog entry and no announcement email.** Per
> `apps/docs/changelog/_README.md`, patches are not published: they roll up into
> the next minor entry, and only minors/majors get a What's New entry and an
> announcement. `v2.4.1`–`v2.4.10` shipped the same way.

## Test plan

1. **CI on the release commit.** `ci.yml` and `Build, Test, and Deploy` green on
   `16ca77bd2`; the required check on `main` is the aggregate
   `Lint, Typecheck, Test`. The phone lane (`e2e-phone.yml`) is deliberately not
   required and is not part of the gate.
2. **Staging rollout.** `Build, Test, and Deploy` deploys `16ca77bd2` to staging
   (OKE) before the tag is cut; the tag is only pushed once that run is green.
3. **Smoke on staging after the rollout.** Sign in → open a workspace chat and
   send a turn → open a preview of an app that POSTs to its own API → open a
   channel with unread and use the N-new pill → attach a >10 MB file → open a
   file in the workspace viewer and use the share link.
4. **Desktop.** The `v2.4.11` tag fans out to `desktop-release-macos.yml` and
   `desktop-release-windows.yml`; `finalize-release.yml` publishes the draft
   only when all four asset workflows complete. It polls, so it has **no
   retry**: if an asset workflow is still red when the poll gives up it logs
   `leaving release v2.4.11 as a draft` and exits 1. That happened here —
   `desktop-release-macos.yml` failed its job, the release stayed a draft, and
   once the macOS run was re-run green, re-running `Finalize Release` published
   it. Fix the asset workflow, then re-run `Finalize Release`; do not re-tag.

## Rollback

- **App / API:** redeploy the previous tag (`v2.4.10`, `65420f10a`-era images)
  through `deploy.yml`; no destructive migration to undo — the new columns are
  additive and ignored by the old code.
- **Desktop:** the previous `.dmg` / `Setup.exe` stay downloadable from the
  `v2.4.10` release; the updater will not offer `v2.4.11` to a client that has
  already been rolled back by hand.
- **If the release is published broken:** `gh release edit v2.4.11 --draft`
  hides it again; the tag stays for forensics.

## Known issues carried into this release

- **The phone e2e lane is not a required check.** A phone-only regression can
  reach `main` without blocking; the lane is run per PR and read by hand.
- **`Upload to TestFlight` fails after a successful upload.** The iOS workflow
  uploads the `.ipa` (`UPLOAD SUCCEEDED with no errors`) and then dies assigning
  TestFlight groups: `app-store-connect.rb:111` does a `GET` on the
  `betaGroups` relationship, which Apple now answers with
  `403 FORBIDDEN_ERROR … The relationship 'betaGroups' does not allow
  'GET_RELATED'. Allowed operations are: CREATE, DELETE`. The build does reach
  App Store Connect; only group assignment is broken. Tracked separately.
- **Not in this release (merged after the tag, ships in 2.4.12):** #1903
  (SHO-301) de-flakes main's merge queue — it fixes the Prisma migrate-retry
  shell test, the `sho285-hosted-workspace` AC4/AC5 timeouts and the
  happy-dom `CustomEvent` contamination behind `message-edit-api.test.ts`; and
  #1897 (SHO-297) rejoins a live turn with a loading state instead of the stale
  half-written reply. Main's merge queue is flaky for this release; both fixes
  landed at 15:38Z and 15:44Z, after `16ca77bd2` was cut.
