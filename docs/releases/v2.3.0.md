# Shogo 2.3.0 release write-up

Drafts of the external announcements for v2.3.0. The in-app What's New and the
docs changelog entry live in `apps/docs/changelog/2026-10-16-v2-3.md`.

Covers everything from `v2.2.0` to the release commit, including the patches
`v2.2.1` through `v2.2.27`, which shipped without release notes.

## GitHub release notes

Prepend this above the auto-generated download block on the published release
(`gh release edit v2.3.0 --notes-file ...`).

```md
# Shogo 2.3: Agents that see big jobs through

In 2.3, your agents take on bigger jobs. They plan the work on a board in your channel, keep going while it runs, and report back when it's done. Your team gets huddles, voice notes, and roles to control who can do what.

## Work boards in your channels

- Ask an agent to organize a project and it sets up a board in the channel, adds cards, and moves them as the work happens.
- A card shows a spinner while an agent works on it, and summaries render as formatted text.
- Work boards are on by default in every workspace.

## Talk the way you want

- **Huddles:** audio and video calls with screen sharing in any channel or DM, on web and desktop.
- **Voice notes:** record, send, and play them in channels and DMs.
- **Profile pictures**, a private **note to yourself**, and **Starred DMs**.
- @-mentions are highlighted, and mentioning someone outside the channel offers to add them.
- Shared files get a card with a preview and a download button. On desktop they open in their own window.
- Archive or permanently delete channels. Click a reaction again to remove it.

## Agents that see long work through

- Agents can run work in the background, wait for it, and wake up when it finishes.
- An agent that hands work to another agent follows it and acts on the result. Replies from long-running projects are no longer lost after 20 minutes.
- Stop reaches tools that are waiting, and the workspace agent can list and stop your running agents.
- Fewer failed turns:
  - An empty model reply is retried once.
  - Under memory pressure, the largest command stops instead of the whole turn.
  - A runtime with work in progress isn't shut down.
- Every plan defaults to Auto. Claude Haiku 5.5 is available, and admins can set the default model for tagged agents.
- Agents can look up Instagram and TikTok profiles. The browser tool tests screen sizes and reads console and network errors.

## Roles and permissions for teams

- Roles for workspaces and projects decide who can view, edit, and manage each one.
- An agent's tools have the same project permissions as the person who asked.
- Share your GitHub account with all of a workspace's agents.
- Each member gets their own chats with the workspace agent.

## A faster start

- Onboarding asks "What do you want to build?" instead of having you pick an agent or a workspace type, and your workspace agent warms up while you type.
- Cloud projects wake up faster after they've been idle.
- Cloud runtime updates reach a project once it's idle, so a project you're using isn't restarted under you.
- Git history is saved in small increments, so saves are faster and more reliable. Git LFS works in cloud projects.

## Also in this release

- **Desktop:**
  - Electron 44, with lower memory use and a faster start.
  - Local and cloud workspaces side by side, with sign in and out from the switcher.
  - On Windows, no more console windows flashing.
- **Activity and analytics:** filter #activity by agent and channel, and open any line in its chat. Usage and cost analytics have their own screen.
- **Mobile:** clearer chat formatting colors, the system photo picker, and the Get started checklist in the sidebar.
- **Upgrades:** hitting a usage limit or the Pro publishing gate now offers an Upgrade instead of a dead end.

## Fixes since 2.2.0

- Notifications arrive on web and iOS.
- The unread badge no longer comes back after you read a channel.
- Pasted lists and tables keep their formatting, and link previews work for large pages.
- Share links work from workspace agents.
- Projects no longer hang on "Starting your project", and Remote SSH projects start reliably.
- Shell commands can use `sudo`, and "Follow agent" no longer switches IDE tabs on its own.
- Long meeting recordings transcribe in full.
```

## Rollback note

2.3.0 changes how the metal fleet stores git history. Each project moves from a
whole-`.git` tarball (`{key}/repo.git.tar.gz`) to a manifest plus git bundles
(`{key}/repo/manifest.json`) the first time it saves. After that, its tarball
is no longer updated. 2.2.27 and earlier only read the tarball.

- **Don't roll the metal agent back past 2.3.0.** A 2.2.x agent would restore
  a migrated project from its stale tarball, without the commits made since
  migration.
- **A Kubernetes rollback is safe, with one caveat.** A 2.2.x api reads the
  tarball for checkpoints and `git clone`, so for migrated projects those can
  show older history until you roll forward again. Nothing is lost, because
  the bundles stay the source of truth.
