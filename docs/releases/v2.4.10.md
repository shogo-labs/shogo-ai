# Shogo 2.4.10 release write-up

Release plan, test plan and rollback notes for **v2.4.10** — a patch on the 2.4
line. Russell asked for it in #go-live on 2026-11-01: "do a 2.4.10 release after
merging `578dc5f7f`".

> **Why there is no changelog entry and no announcement email.** Per
> `apps/docs/changelog/_README.md`, patches are not published: they roll up into
> the next minor entry, and only minors/majors get a What's New entry and an
> announcement. `v2.4.1`–`v2.4.9` shipped the same way.

## What goes live (v2.4.9 → main @ `37aadd950`)

8 commits, 107 files, ~8.2k insertions, 2 Postgres + 2 SQLite migrations.

| Area | Changes | Test on staging |
| --- | --- | --- |
| **OpenRouter attribution** | #1870 (SHO-281) — OpenRouter takes at most **two** `X-OpenRouter-Categories` values per request and silently drops the rest, so the 3-item default never recorded `personal-agent`. The header now carries a rotating window of two (`openRouterCategoriesForRequest`), and OpenRouter merges categories across requests (cap 10), so all three get recorded within a couple of turns. Any `OPENROUTER_CATEGORIES` override of any length still fits; the header is omitted when the list parses empty. | After deploy, a couple of Hoshi turns → `openrouter.ai/apps?url=https://shogo.ai` lists `personal-agent` alongside `cloud-agent` and `native-app-builder`. |
| **Crashed turns (SHO-274)** | #1861 — a crashed turn keeps its prompt and the reply already streamed: `InflightTurnMarker` checkpoints `partialText`/`partialReasoning` (32k tail, ≤ every 2 s), the prompt is persisted before the model call, and `recoverInterruptedTurns` appends the streamed text as a finished assistant message closed by `[interrupted here]` so the resumed model continues instead of restarting. #1869 — a machine refusal met by a chat turn is reported from the transport fetch, so a sleeping workspace says so instead of failing silently. | Kill the app mid-turn → reopen → the prompt and the streamed text are both there, closed by `[interrupted here]`, and the turn resumes. Open a chat on a sleeping machine workspace → the banner names the machine state. |
| **Machine sync (SHO-276)** | #1865 — the snapshot finishes (byte-bounded pages, resumable under the same epoch, 90 s deadline, one `findMany` per model); one machine is one row (`Instance.deviceId` + `x-shogo-device-id`, hostname-only rows adopted, duplicates retired by device id); the cloud never writes into a machine copy (reattach candidates exclude machine workspaces, `postInterruptedResume`/`dispatchNext` no-op, a completed snapshot prunes rows the desktop never sent). | Desktop → cloud move of a workspace with many rows: the snapshot completes, the machine appears once after a hostname change, and the cloud copy is not written to. |
| **Phone** | #1862 — Slack-style channel header: a pill showing `N members • M tabs` (or the open board/doc name) that grows a glass panel with Notify / Star / Add, the tabs, and the channel actions; no dimmed backdrop, header fades, ~0.24 s. #1868 (SHO-280) — file chips re-render when the file index arrives: the index reaches `FileAwareLink` through a `FileExistsContext` provider instead of Streamdown's `components` map (whose outer `memo` does not compare `components`), and a finished turn re-reads project lists in place instead of clearing them. | Phone: open a channel → tap the pill → the panel grows out of it and closes back into it; desktop keeps the tab strip. Send a turn that writes a file → the chip appears without a reload. |
| **Load tests (SHO-277)** | #1866 — local load tests for many agents plus the four fixes they point at: a real-relay load test (30 projects, 200 sessions, 350 KB turns, N concurrent turns) gated on `SHOGO_LOAD_TESTS=1` and dispatchable through the non-required `api-load.yml`, a desktop nav-under-load Playwright spec (opt-in), an orphan-child-ledger reap test, and `snapshot-write-budget.test.ts` which runs on every PR. | Nothing user-visible; the machine-independent half (writes/bytes per turn, persisted turn matching the stream byte for byte) runs on every PR. |
| **Test-only** | #1867 (SHO-279) — deflake the chat-composer-memory AC 3 stress (no pointer input under CPU throttle). | — |

## Migrations (all additive)

- Postgres `20261031120000_sho274_chat_turn_frames` — new `chat_turn_frames`
  table (append-only write-ahead turn journal) + two indexes.
- Postgres `20261031150000_add_instance_device_id` — `instances.deviceId` (nullable)
  + `instances_workspaceId_userId_deviceId_idx`.
- SQLite mirrors of both under `apps/desktop/prisma/migrations/`.

## Tagging

1. `git tag -a v2.4.10 -m "Shogo 2.4.10" 37aadd950 && git push origin v2.4.10`.
2. Watch `deploy.yml` for the tag: promote-images → deploy-us → deploy-eu →
   metal-runtime-image → dispatch-metal-agent-release → SDK publish. Desktop
   builds (macOS, Windows) and the agent-runtime / worker tarballs attach to the
   same GitHub release; `finalize-release.yml` un-drafts it only when all four
   asset workflows succeed.
3. Post-deploy checks: `/api/version` reports `2.4.10` in US **and** EU, the
   runbook's post-roll checks (`docs/runbooks/deploy-prod.md`), a phone app on
   the new build (channel header panel, file chip), one crashed-turn recovery,
   and no new SigNoz alerts for an hour.
4. No announcement email and no changelog entry — this is a patch.

## Rollback note

`deploy.yml` with `release: v2.4.9` and `dry_run: true` first, then for real.
Both migrations are additive, so a rollback to 2.4.9 leaves the new table and
column in place and the older code ignores them; no down-migration is needed.
